恶意宿主样式压力测试

这个页面在干什么

页面上方注入了一整套元素选择器规则 —— * { box-sizing: content-box }、 div { margin: 20px }、button { all: unset }、 svg { width: 96px; height: 96px }。 如果组件外观看上去仍然正常，说明"单类名 + head.prepend()"这套打法成立。

为什么这样就能赢

CSS 层叠先比权重：我们的规则全是单类名（0,1,0），宿主的 div / button 是元素选择器（0,0,1）， 宿主输，污染进不来。

而使用者想覆盖我们时，写同权重的 .tdw-bubble {} 即可 —— 因为我们的样式表是 head.prepend() 插到最前面的， 同权重时文档顺序在后者赢，所以使用者不需要写 !important。

这一档挡不住什么（诚实的边界）

纯 DOM、不用 Shadow DOM 的前提下，下面这类规则仍会击穿：

#app div { margin: 20px }        /* 带 id 的高权重选择器 */
body div.chat-host > * { ... }   /* 叠了多层的高权重 */

这是使用者的选择（"不做样式隔离"），换来的是 UI 可以被完全重构。 真的遇到这种宿主时，用 injectStyles: false + getChatStyles() 接管样式表 —— 见 custom.html。

  • 点开右下角的按钮，检查：面板圆角、阴影、气泡配色、图标大小是否都正常。
  • 检查 <svg> 图标有没有被撑成 96×96 的巨型方块。
  • 检查输入框有没有被 magenta 点线边框和 22px 字号污染。
  • 检查每条消息时间戳有没有被 text-transform: uppercase 影响（时间戳本来就该是原样）。
